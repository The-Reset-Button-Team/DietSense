IEEE System Architecture Specification

DietSense: A Multimodal, Safety-Gated Hybrid ML Diet Planning Architecture

The-Reset-Button-Team • Personalized Metabolic & Solo-Cook Nutrition Engine

Abstract—DietSense is an end-to-end intelligent dietary decision support system designed for solo living. The architecture decomposes meal planning into five sequential stages: (I) User biometrics and multimodal grocery inventory extraction, (II) Pre-scoring hard safety constraint gating against authoritative databases (USDA FoodData & ICMR-NIN), (III) Six-factor hybrid recommendation scoring with SHAP explainability, (IV) Dynamic proportional macronutrient validation, and (V) Adaptive closed-loop preference learning via Ridge Regression.
FIG. 1. End-to-End System Block Diagram (Sequential Pipeline Architecture)
LAYER 1: DATA INGESTION & USER ACQUISITION Inputs
1.1 Biometrics & Goal
Weight, Height, Age, Biological Sex, Activity Level, Target Goal (Cut/Maintain/Surplus).
1.2 Solo Routine Matrix
Meal Frequency (2, 3, 4, 5 slots), Weekday Effort Profile (Low <12m, Moderate 25m).
1.3 Vision OCR Ingestion
Multimodal OCR on receipt slips, digital delivery PDFs (Blinkit/Zepto), & fridge images.
↓ [Structured Inputs & In-Stock Inventory]
LAYER 2: KNOWLEDGE BASE & HARD SAFETY GATE Deterministic Filter
2.1 Verified Nutrition DB (Rule 1)
8,788 USDA FoodData + 528 ICMR-NIN IFCT foods. No LLM hallucination of macro/calorie values.
2.2 Hard Safety Gate (Rule 2)
SQL pre-filtering for allergens (nuts, dairy), vegetarian, gluten-free, & medical contraindications.
↓ [Safe Candidate Recipes & Calorie Bounds]
LAYER 3: CORE ALGORITHMIC & HYBRID ML ENGINE Core Processing
3.1 Metabolic Target Calc
Mifflin-St Jeor BMR × Activity ± Deficit.
Target = max(1200, TDEE - 400)
3.2 6-Factor Hybrid Scorer
Score = Σ w_i · s_i
Macro (0.30), Goal (0.20), Pref (0.20), Feedback (0.15), Div (0.10), Prep (0.05).
3.3 Dynamic 100% Validator
Proportionally distributes calories, carbs (50%), protein (20%), fats (30%) across active slots.
↓ [Optimized Daily Meal Plan & SHAP Attributions]
LAYER 4: HINGLISH EXECUTION & UI Output
  • • Pantry Matching: 100% In-Stock vs missing flags.
  • • 1-Person Portion Guide: Metric & kitchen spoons.
  • • Hinglish Steps: Clear cooking guidance with heat levels & single-pan cleanup hacks.
LAYER 5: ADAPTIVE FEEDBACK LOOP Learning
  • • Post-Meal Rating: 1 to 5 stars + feedback tags.
  • • Ridge Regression: Updates preference_weights vector in PostgreSQL.
  • • Feedback Loop: Re-ranks future candidate dishes.
Fig. 1. Layered Architectural Flow of the DietSense Decision Engine. Data moves strictly top-to-bottom with closed-loop feedback from Layer 5 back to Layer 3.

Mathematical Formulations

1. Energy Expenditure (Mifflin-St Jeor):
BMR = 10·W + 6.25·H - 5·A + (Male ? +5 : -161)
TDEE = BMR × ActivityMultiplier
Target = max(1200, TDEE - 400) [Cut]
2. Recommendation Objective Function:
Score(r) = 0.30·S_macro + 0.20·S_goal + 0.20·S_pref + 0.15·S_fb + 0.10·S_div + 0.05·S_prep
∀ S_i ∈ [0, 1], Σ w_i = 1.0
